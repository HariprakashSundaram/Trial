How timing is calculated

Request duration is HAR entry.time (milliseconds), with fallback to the sum of nonnegative timing phases. Total elapsed capture time is the span from the earliest request start to the latest request finish; summed request durations are shown separately because concurrent requests overlap. Request intervals use startedDateTime + entry.time, merge overlaps, and measure gaps between intervals. Entries without valid start timestamps cannot be placed on the waterfall. The same endpoint called multiple times in one file is aggregated by average duration; call count and maximum duration are also available.

Call comparison

Total response time sums the duration of EVERY request in each HAR, including requests under 1 second and requests hidden by the slow-call filter. It is not wall-clock elapsed time. Waterfall elapsed spans the first request start through the last request end, including idle gaps. Active network time merges overlapping request intervals and excludes idle gaps.

Calls are matched by the selected key. Blank cells mean that call is absent in that sample. The Average column averages only samples containing the call. Consecutive duplicate HTTP calls

Detects the same request key repeated immediately after itself in chronological HAR start order. A run of 4 calls counts as 1 unique call and 3 duplicates. Non-consecutive repetitions are not counted as consecutive duplicates. Matching follows the selected Match calls by setting.
